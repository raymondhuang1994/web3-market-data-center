# Web3 市场数据中心 · PRD

版本：v0.1｜状态：待用户确认，尚未授权开发与发布｜文档日期：2026-09-15（取样于 9 月 14 日夜间）

## 1. 产品结论

面向高管和营销团队，建设一个公开访问的 Web3 市场数据中心，并交付可维护的 GitHub 项目。沿用吴说数据中心的栏目层次、摘要卡片、图表与明细表结构，改善视觉层级和阅读体验。只覆盖用户指定的 CEX、DEX、代币化股票、Hyperliquid，并保留 AI 解读。

第一版的质量标准是：打开即可看到有依据的市场规模、平台份额和变化；能继续查看明细、历史、口径与数据日期；暂未接通的内容如实保留。不能用大量空页面、静态截图或未经标记的演示数值来计算实现比例。

本轮授权仅包括只读调研和编写 PRD / Spec。本文中的技术栈、路由、时间、门槛和推荐选项均为待确认方案；没有安装新插件、申请接口、创建 GitHub 仓库、启用任务或部署网站。

## 5. 指标与数据要求

### 5.1 DEX 市场份额

推荐现货 DEX 与永续 DEX 分开呈现，作为同一专题的两个视图；是否采用由 D-01 决定。采用两个视图不代表永续数据已免费可用，暂缺时保留其状态。

主要指标为协议成交额、成交份额、份额变化、排行和历史走势。全链 / 单链与 24h / 7d / 30d 选择只在来源支持可比口径时开放。具体要求：

- 份额分母明确为同来源、同期间、同市场类型、同链范围内的已覆盖协议成交总额，不宣称覆盖全行业。
- 协议父子版本、多链记录和聚合器去重；Hyperliquid 永续不混入现货分母。
- 滚动 24 小时和 UTC 日历日分开标注。份额变化用百分点，成交额变化用百分比。
- “其他”必须是同一分母内真实的其余协议之和；缺失值不得按 0 补足。
- 没有逐协议历史时，显示当前份额并自接入日起积累历史，不用总量历史虚构份额走势。

### 5.2 CEX

现货与合约分开统计。单平台或已覆盖平台不能标成全市场。原站 CEX 样本实际含 Hyperliquid、Uniswap 等场所，需保留真实类型和样本说明；如果改成严格 CEX 集合，需先批准重算范围。储备资产、净流入、客户资产与偿付能力是不同概念。持仓的币数量、美元名义金额和合约张数保留原始单位，并在有转换依据时计算派生值。

原“储备可信度”是作者手工研究模型，不是通用客观指标。建议保留视图位置并显示“研究口径待确认”，不搬用评分和研究文案；是否另做自有评分由 D-08 决定。

资金费率展示实际结算间隔；跨平台对比前按已确认规则统一期间。原站的 OI 加权和成交加权不混用。异常年化费率不能直接描述成可获得收益。

### 5.3 代币化股票

标的至少区分基础资产、发行方 / 包装形式、平台、链、合约地址或市场 ID、报价币及产品类型。原生股票、股票代币、永续合约不是可互换的同一条记录。原热门板块实际包含按标签聚合的永续市场；原 TradFi 套利使用股票 / 商品 / 指数参考报价与永续报价比较。页面必须明确这些产品类型。新增真正的股票代币现货专题属于可选建议，并非默认加入。

跨平台价差保留页面，但必须核对合约乘数、价格单位、更新时间和交易时段。缺少可比买卖报价时只描述参考价差，不能计算成可执行套利利润。原站热门板块和稳定币专题保留独立统计口径。

### 5.4 Hyperliquid 与 Robinhood Chain

Hyperliquid 默认永续市场、HIP-3 子市场、现货、HyperEVM DEX、HIP-4 等分别记录。已接通默认永续接口不能代表原站七个视图全部实现；HYPE 代币价格也不能代替协议成交或收入。

Robinhood Chain 使用链及协议口径；钱包活跃地址不等于独立用户。源站 Dune 查询需保留查询 ID、时间范围和结果更新时间，不能把原站能读取某结果视为本项目已经取得 Dune 自动执行权限。

### 5.5 AI 解读

保留栏目。接入真实模型时，仅使用通过校验的本版指标，给出简短中文解读、引用的指标与日期。推荐内容为市场变化、平台份额变化、需要进一步关注的数据，不复制原站结论。

生成条件：来源已确认、数字单位无异常、日期和比较期可用。缺少数据时减少结论；不补造数字、不将相关性写成因果、不从超出本版范围的新闻扩展内容。

模型、免费额度与后台使用身份尚未确认。按 D-03 选择保留“AI 解读待接入”，或将规则模板输出明确标成“数据摘要”；规则输出不能冒称 AI 解读。

## 7. UI 与内容设计

建议方向：浅灰底、白色卡片、深色正文、单一蓝色强调色，保留原站紧凑的工作台式布局；改善留白、对齐、图例和数字可读性。正文约 16px，常用标签至少 14px；涨跌同时提供符号与数值，不只靠颜色。

## 9. 第一版效果与实现比例

### 9.1 两个分母分别报告

1. **页面与结构完成率**：获批路由、内部视图、关键交互中完成的数量 / 获批总数量。目标 100%，但占位内容只代表结构完成。
2. **可公开使用的数据组件覆盖率**：具有真实数据、正确口径、可用时间、来源记录且完成公开使用核验的关键组件 / 获批关键组件总数。暂缺、异常、未核验授权、演示数据均不计为已接通。

在开发前固定组件清单及分母。图表、摘要和表格若展示同一基础指标，不通过重复计数提高比例。删除模块改变分母必须用户批准。

### 9.2 建议验收门槛（待确认，不是当前成果）

- 整体关键数据组件覆盖率目标 ≥80%，并逐专题公布分子、分母和缺口。
- 总览关键事实组件目标 100% 有有效数据；存在缺口则直接列明，不把暂缺卡片算作成功。
- 每个顶级业务组至少有可用的核心图表与明细；若某组核心内容仅为占位，不称为完整第一版。
- 视觉、交互、移动端、日期与错误状态完成验证。
- 首发前连续 3 次定时运行或跨 3 个实际日观察无静默失败；手动回放不等于跨日验证。

目前仅完成有限样本核验，不能声称已实现 80%。若免费来源无法达到目标，提交“缺项—原因—免费替代是否同口径—可选付费方案”，由用户决定接受当前覆盖、继续核验或调整范围。
